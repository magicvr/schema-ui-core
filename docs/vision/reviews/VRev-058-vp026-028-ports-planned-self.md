# VRev-058 · VP-026/027/028 端口 VP 计划审视

## 背景与触发

用户裁决（2026-08-31）：缓存 / 限流 / 事件总线按 **3 个独立 VP** 立项——分组标准为"触发条件独立 × 关门能力独立"，取代前两轮"演化轨道相似即合并"的弱依据。三 VP 均 `planned`、0 区、`vision_ref` = `schema-ui-core-admin-foundation@0.4.0`，承接 Charter 0.4.0 成功边界 #6（同进程基座基础设施端口早期化）与 H-002。本审视覆盖三份 VP 文件的意图、退出判据、非目标、信息需求与相邻边界。

## 审视要点

### 1. 分组标准正确性（3 个独立 VP）

**pass**。三端口的触发条件强度确实不同：缓存（C 端业务域接入即需要，高确定性）、限流（防刷伴随出现，但内存默认有意义的中间态）、EventBus（跨模块解耦才需要，最弱）。合并会使关门互相拖累（未消费交付物审查 / 触发未到却要交付）。3 个 VP 各自一能力一关门，符合本项目 VP-013～VP-025 单能力族既有模式。

### 2. 与 Charter 0.4.0 对齐

**pass**。三 VP 均属架构分支，承接成功边界 #6 的"基础设施端口开放"与 H-002 的"同进程基座主要预期形态"；不改变目的/边界/非目标；"不预制 Redis/outbox/broker"与成功边界 #6"缓存、限流扩展、队列等有状态横切能力在业务域模块触发时由架构分支按需交付，不预制"一致——本波交付的是**端口 + 进程内默认**，不是有状态外部实现，不构成预制矛盾。

### 3. 各 VP 退出判据可判定性

**pass**。

| VP | 判据可判定性 |
|----|-------------|
| VP-026 | 端口契约可快测（Get/Set/Delete + TTL + 并发）；双策略+可插拔可断言；内存供应商（有界+清理+驱逐）可测；Redis 接缝声明可核验（不引入客户端依赖）；D-001 共享约定登记可核验 |
| VP-027 | 端口契约可快测；滑动窗口内存供应商（演进 loginRateLimiter）可测；**既有使用点迁移不回归**（登录/captcha/recovery/MFA 的 D-001 P1 防护测试）可核验；Redis 接缝声明可核验 |
| VP-028 | 端口契约可快测（订阅/退订/错误语义）；channel 进程内实现可测（并发/顺序/panic 隔离）；outbox/MQ 接缝声明可核验；与 Admin 扩展接缝对齐可核验 |

### 4. 非目标与边界卫生

**pass**。三者互为独立边界（缓存≠限流≠消息）；与 RT-Q02/Q03/Q05 的 trigger-gated 语义衔接正确（承接端口/接缝，外部实现仍 gated）；不重开 VP-012 及其它 closed 记录；明确"调度去重 map 不是限流""mail cachedAdapter 迁移不强制"等边界判断，避免范围滑移。

### 5. 信息需求（P-005）

**pass**。三 VP 的 I-0NN 项均标注 required/non-blocking 与最晚阶段；关键 API 形态、TTL/清理语义、投递/错误语义、迁移策略均按 required 登记待裁决，未伪装为已决定。

### 6. 组合编排同步

**pass**。roadmap 已原子同步（组合编排表 +3 行；RT-Q02/Q03/Q05 承接注记）；revisions.md 已登记 VR-053；workspaces.md 无需更新（无开区）。
