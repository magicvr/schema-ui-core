## 待响应意见摘要

A-005（independent · grok-build · conditional）：1 required（**F-001**）+ 4 recommended（F-002～F-005）。

- F-001：`composition.go` 的 `OwnerExistsFunc` 把 `SubjectExists` OR 进 **user 自动开户 HTTP 门禁**——已登记 `subject_id` 可过门禁开出无 `admin.users` 行的 `owner_type=user` 孤儿账本；by-owner 门禁应只查 user 表。

## 修复事实（按时间线）

1. **代码修复**（`apps/api/internal/composition/composition.go`）：`walletOwnerExists` 闭包改为**只查** `authRepository.UserByID`；删除 `SubjectExists` OR 分支；注释更新为「by-owner HTTP 面只开 USER 账户，门禁只查 live user 表；主体存在性留在 `CreateAccount(owner_type=subject)` / 凭证 `Redeem`（`SubjectExists`）」。handler 层不动（POST by-owner 通过门禁后固定 `GetOrCreateUserAccount`，repo 硬编码 `owner_type=user` 不变；`CreateAccount`/`Redeem` 的主体校验原本就在服务内）。
2. **回归测试**（新增 `apps/api/internal/composition/wallet_owner_gate_subject_test.go`，`TestWalletByOwnerGateRejectsRegisteredSubject`）：按生产顺序引导（open store → `Bootstrap` admin → newMux 以生产贡献清单 Reconcile 一次，避免 testsupport 部分清单 checksum 漂移）；注册真实外部主体后——
   - `POST /api/wallet/by-owner/{subjectID}` → **404 USER_NOT_FOUND**，`wallet_accounts` 无 `owner_type=user` 行；
   - `POST /api/wallet/by-owner/{subjectID}/adjust` → **404 USER_NOT_FOUND**，仍无 user 行（同门禁资金路径）；
   - 阳性对照：`POST /api/wallet/by-owner/user-admin` → 200，user 账本 1 行。
3. **阴性对照（修复前行为复现）**：暂存修复后复跑同用例 → **FAIL**，服务端 200 并返回 `ownerType:"user"` 新账本（与 A-005 F-001 描述一致）；恢复修复后 → **PASS**。测试对回归敏感。
4. **附带修复（既有基线缺口，与 F-001 无关）**：全包回归发现 `TestPublishedManifestNavigationOrder/admin_default_order_matches_the_frozen_list` 在 HEAD 亦红——R3（GOAL-003）注册的 `menu_wallet_vouchers`（Order 11）未进冻结列表。`composition_test.go` want 列表追加 `"Prepaid vouchers"`（附 VP-029 R3 注释），以实际注册序为冻结真相。
