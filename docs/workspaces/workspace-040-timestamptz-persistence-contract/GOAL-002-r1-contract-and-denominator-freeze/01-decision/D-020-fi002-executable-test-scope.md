# D-020 · F-I-002 可执行测试的载体与重定向（用户 P-004 裁决）

## 决定的来源

- A-038（independent · grok-build grok-4.6 · high）指出 **F-I-002** 整条现在只剩一项实质剩余：「用例仍是 ID；**非法/越界可执行测试未发生**」。
- 该剩余项存在**结构性死锁风险**：F-I-002 阻断 C2 冻结 → C2 冻结阻断 R2 → 而「可执行测试」若必须在真实迁移代码上跑，则需 R2。三条互相锁死。
- 用户 2026-09-20 经 P-004 裁决：**选项 A**。

## 决定

### 1. 允许在**一次性验证库**上跑（R1 内闭合）

- F-I-002 要求的可执行负值/越界/边界测试，**允许**在**一次性验证库**（`:memory:` 或临时文件）上运行。
- 测试用**冻结候选的 DDL 与表达式**建旧表、跑 rebuild、做断言；**不触碰**生产 schema、迁移、仓储或夹具，因此**不违反**「C2 冻结前不得实施 schema 变更」的门禁。
- 落点：`apps/api/internal/w040contracttest/`（**仅测试**的独立包，紧邻 `internal/store`，无生产代码）。

### 2. R2 必须把同一批用例**重定向**到真实转换迁移

- R2 落码后，同一批用例（负值、999 ms 无进位、历元 0、公元 9999 年、NULL 保留、sentinel 0 → NULL、voucher 0/NULL、负毫秒 floor、fixed-6 词法序）必须改为**针对真实 conversion migration** 运行。
- **冻结候选的 DDL 或表达式变更时，该测试文件必须同步更新**（它是合同的执行化身，不是实施）。

## 理由

- 满足 A-027/A-030/A-038 对「可执行测试」的字面要求，同时不越过 C2 门禁。
- 一次性库上的断言能直接暴露合同级缺陷——**本轮实测即已暴露两处**（见 §影响），证明其有效。
- 避免死锁，使 F-I-002 可在 R1 内合法闭合。

## 未选方案

- **B：必须绑定真实迁移代码** → F-I-002 在 R1 内无法闭合（R2 被 C2 未冻结挡住），需另定放行顺序。用户未选。
- **C：拆分为「设计在 R1 关 + 测试作为显式 accepted-residual 移交 R2」** → 会把可执行验证推迟到 R2，等于 R1 关门时仍无任何执行证据。用户未选。

## 影响与边界

### 该测试**已经**产出的两处实测发现（本轮）

1. **负值政策被过度泛化**：测试初稿对所有时间列一律「负值即 fail closed」，被测试自身拦住。核对权威决策后确认——**Root `D-012` 的负值 fail-closed 是 voucher 专属**；**Root `D-015` 明确「负 epoch 不是 sentinel」，是合法 instant，正常转换**。测试已按此收正，并把该区分固化为可执行断言。
2. **年份 9999 的毫秒用例**：初稿把秒值当毫秒值传，测试立刻报出 `1970-01-21` 而非期望值——被测数据的单位错配被捕获。

### 边界

- 本决定只确定**测试载体**；**不等于** F-I-002 已闭合——闭合与否由 independent 复审判定。
- 本轮新增目录 `apps/api/internal/w040contracttest/` **只有测试文件**，无生产代码；`go build ./...` 仍 exit 0，`go vet` 通过。
- 本决定不改变 `D-017`（单 checksum）、`D-018`（行拷贝机制）、`D-019`（FK 重建模式）。
