# E-002 · A-002 F-001 响应修复

## 背景

independent A-002（grok-4.5 · high · audit）发现 P0 batch-delete 修复引入**批级 last-admin 绕过**（F-001 · required · high）：`DeleteUsersBatch` 原守卫为 per-id `countAdminUsersExcluding(tx, id)`，批内含**全部** admin 时，每个 id 检查时其他 admin 仍在（通过），随后统一删除 → **0 admin**。持 `users.write` 的非 admin 可在 ≥2 admin 时清空管理员。独立探针：`DeleteUsersBatch([user-admin, user-admin2], external)` → 0 admin。

## 修复

- `users_repository.go` `DeleteUsersBatch`：守卫阶段统计批内 admin 数；若 >0，用 `countAdminUsersExcludingBatch(tx, keys)` 统计**不在选择集内**的 admin 数，为 0 → `ErrLastAdmin`（整批回滚）。per-id last-admin 检查移除（批级判定严格覆盖且语义正确）。
- `countAdminUsersExcludingBatch`：`SELECT COUNT(*) ... WHERE r.key='admin' AND ur.user_id NOT IN (?,...)`，占位符由去重后的 keys 生成。

## 回归

- 仓库层 `TestDeleteUsersBatchRejectsRemovingAllAdmins`：全 admin 批 → ErrLastAdmin 且零删除；含 viewer 的批同样拒绝且回滚；存活 admin3 时同批合法。
- HTTP 层 `TestUsersBatchDeleteRejectsRemovingAllAdminsHTTP`：非 admin（users-manager）actor 批含全 admin → 409 LAST_ADMIN 零删除；admin3 存活后同批 200 并删除。
- 既有 `TestDeleteUsersBatchAtomicRollback`（自删/last-admin/not-found/dedupe 回滚）保持绿。
- `go test ./...`（apps/api）22 包全 ok。

## 边界说明

- actor 在批内仍优先 `ErrSelfOperation`（守卫顺序：exists → self → admin 统计），与单条 `DeleteUser` 语义一致。
- 去重后空批直接返回 0（不进入事务守卫）。
- 单条 `DeleteUser` 行为不变（本就无此绕过）。
