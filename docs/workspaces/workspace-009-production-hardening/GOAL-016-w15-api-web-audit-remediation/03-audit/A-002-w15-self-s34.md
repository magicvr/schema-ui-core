### F-002 · 非 dev JWT secret 强度 — 证据通过

### F-003 · bootstrap 密码策略 — 证据通过

- `modules/authsession/password_policy.go`：导出 `ValidateSeedPassword`（8–72 字节、非空；复用 `policyMinLengthFloor/Ceiling`，与 0057 播种默认等价）。
- `cmd/server/main.go` `resolveSeedHash` + `server/serve.go` `bootstrapAdmin`：非 dev 先策略后 bcrypt，fail-closed；dev `admin` 回退不变。
- 负例：`cmd/server/main_test.go`（缺省/weak/7/73 字节 → fail；compliant → pass；dev 保持）；`serve_test.go` `TestRunRejectsWeakSeedPasswordNonDev`（监听前失败）；`password_policy_test.go` `TestValidateSeedPassword`（7/8/72/73 + 空白边界）。
- 核验点：仅两个 hash 入口点均已覆盖；HTTP 面用户改密仍走 `ValidateNewPassword`（可配置策略行），语义不重叠。

### F-004 · MFA step-up 一次性语义 — 证据通过

- `modules/mfa/service.go` `requireActiveSecondFactor`：`ValidateTotp` 成功取匹配 step → `repo.AdvanceLastUsedStep(userID, step, now)`（CAS，与登录路径同语义）→ CAS 失败（`advanced=false`）→ `ErrMFAInvalid`；`maybeRewrap` 仅赢者执行。
- 负例：`TestServiceStepUpTotpReplayRejected`（同码二次 rotate 拒绝、VerifySecondFactor 重放拒绝、下一 step 新码可用）。
- 核验点：disable / recovery rotate / self-recovery gate 三调用方共用同一 helper，一次性语义单点覆盖；失败注入 `ErrMFAInvalid` 会触发 handler 侧 step-up 限流计数（W13 语义兼容）。

### F-005 · 邀请 token URL 清理 — 证据通过

- `apps/web/src/components/invite-accept.tsx`：挂载读取 token 后立即 `history.replaceState` 删除 query `token`；读取失败回退空串；成功跳转不变。
- 核验点：token 生命周期 = 单次 filter 读取 → 立即 scrub → 仅 state 持有；一次性 bearer + 默认 7 天 TTL 的 URL 留痕面消除。React StrictMode 双挂载下第二次挂载 query 已无 token → 幂等。
