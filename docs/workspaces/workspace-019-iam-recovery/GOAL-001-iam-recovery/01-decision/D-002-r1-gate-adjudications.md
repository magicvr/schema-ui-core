# D-002 · R1 门禁三项用户裁决（I-001 / I-002 / I-009）

## 背景

R1 合同冻结立项前置（E-001）：须先关闭 I-001 / I-002 / I-009 三个 required 信息项（P-005 · 用户裁决路径）。2026-08-25 用户在结构化裁决会话中就三问逐一选定（问题 id：`i001_proof_form` / `i002_ttl_cooldown` / `i009_mfa_boundary`），三项均为书面裁决留痕。

## 裁决结果（冻结输入）

| ID | 问题 | 裁决 |
|----|------|------|
| I-001 | 自助恢复证明形态 | **6 位邮箱验证码**（VP-019 默认候选正式确认；魔术链接未选） |
| I-002 | 恢复码 TTL / 重发冷却 | **对齐 VP-018 冻结数值：TTL 10 分钟 / 重发冷却 60 秒 / 连续错 5 次作废当前挑战**（更紧的 5 分钟档未选） |
| I-009 | MFA 账号自助恢复边界 | **完成设新密码前要求第二因子（TOTP 现时码或恢复码）；无法提供第二因子者走管理员重置**（拒绝自助与绕过两案未选） |

## 裁决含义（供 GOAL-002 合同冻结直接引用）

- **证明面**：与 VP-018 `generateEmailCode` 同构的 6 位数字码；投递只经 `kernel.MailSender` 现行渠道；无生产渠道时 dev/验收从 mock 出站记录取码。
- **时效面**：恢复挑战沿用 `10 min TTL / 60 s 重发冷却 / 5 次失败作废`（对照 `apps/api/internal/modules/authsession/email_identity.go:31-36` 冻结常量）；码 sha256 落库、恒时比较。
- **MFA 面**：封死「仅持邮箱访问权即绕过 TOTP 改密」的旁路（V-F076 关切）。第二因子校验复用 admin.mfa `Verify` 语义（TOTP 或一次性恢复码）；管理员重置走既有 `POST /api/users/{id}/mfa/reset` 特权路径（该实现同时清除 MFA 登记，账号回到无 MFA 状态）。未登记 MFA 的账号不受影响。

## 为什么

- 三项均与既有已关门波次（VP-017/018）和既有模块（admin.mfa）的冻结语义同构，实施面最小、用户心智一致。
- I-009 若选「绕过」即构成 V-F076 明示要防的旁路；选「要求第二因子 + 缺失走管理员重置」在安全等价于「拒绝自助」的同时保留自助通道。

## 未选方案

- 魔术链接：需新增一次性 URL 令牌语义与前端路由，改动面大且依赖邮件客户端点击行为（用户未选）。
- TTL 5 分钟档：暴露窗口更小但慢速用户更易过期（用户未选）。
- MFA 拒绝自助只走管理员重置：安全性等价但自助率为零（用户未选）。
- 允许绕过第二因子：构成 MFA 旁路，否决。
