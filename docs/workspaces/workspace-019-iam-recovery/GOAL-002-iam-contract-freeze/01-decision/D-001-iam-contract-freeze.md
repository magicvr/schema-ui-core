# D-001 · R1 IAM 合同冻结（自助恢复 / 密码策略 / 邀请入职）

## 背景

Root D-002 已关闭 I-001 / I-002 / I-009（立项门禁）。2026-08-25 用户在第二轮结构化裁决会话中就剩余五项书面选定（问题 id：`i003_policy_defaults` / `i004_invite_form` / `i005_invite_lifecycle` / `i007_existing_accounts` / `i008_session_semantics`，均取推荐项）。至此 I-001～I-009 全部关闭，本目标将裁决结果与 VP-019 已冻结项合并为可实施合同。

## 合同条款（冻结）

### §1 自助恢复状态机

- **发起资格**：登录页「忘记密码」发起；服务端按账号标识（用户名或其已绑定邮箱，UI 口径 R2 定稿）定位**唯一**账号。投递目标恒为该账号**已绑定且已校验**的 `users.email`——绝不向发起请求里自带的地址投递。
- **无邮箱边界（I-006 投影）**：未绑定或未校验邮箱的账号不进入自助流程（受控负响应，不发送任何邮件）；该类账号走管理员重置特权路径。
- **证明形态（I-001）**：6 位数字验证码，与 VP-018 `generateEmailCode` 同构；码 sha256 落库、恒时比较；挑战一次性（成功消费即删）。
- **时效（I-002）**：TTL 10 分钟；重发冷却 60 秒；连续错 5 次作废当前挑战（须重发）。数值与 VP-018 冻结常量一致。
- **运输**：只经 `kernel.MailSender` 现行渠道；dev/验收从 mock 出站记录取码。
- **MFA 门（I-009）**：已登记 MFA（active TOTP）的账号在校验码通过后、设置新密码前，须再通过一次第二因子校验（TOTP 现时码或未用过的恢复码，复用 admin.mfa `Verify` 语义）。无法提供第二因子者不能自助完成，走管理员重置（既有 `POST /api/users/{id}/mfa/reset` 特权路径，该实现同时清除 MFA 登记）。
- **完成动作**：校验码（+ 第二因子）通过后设置新密码；新密码必须过当时生效的密码策略（§2）；完成即撤销其余会话（§5）。完成后是否直接签发会话属 R2 设计定稿项（默认建议：回登录页重新登录）。

### §2 密码策略

- **配置面（VP-019 已冻结投影）**：策略 UI 仅 `admin.settings` 既有 tab 扩展（与邮件 tab 同形）；强制面在 `core.auth-session` 对全 Profile 生效；禁止为策略把 `admin.settings` 加入 mvp 默认集、不改模块矩阵 / Manifest 装配语义。
- **默认参数（I-003，起步宽松）**：默认 = 现行行为——最小长度 8 字节（上限维持 72 字节 bcrypt 约束）、复杂度要求关、历史检查关。可配置项 = 最小长度、复杂度字符类别数、历史深度；管理员可在设置面收紧。
- **强制点（四口统一）**：创建账号、管理员重置、自助恢复、自愿改密设定的新密码一律过当时生效策略；管理员重置继续走 `must_change_password` 特权路径不受影响。
- **既有账号生效边界（I-007，渐进）**：策略仅在上述四个设密时刻强制；不做存量密码扫描、不在策略变更时登出或阻断既有账号登录。

### §3 邀请入职

- **形态与建号（I-004，双形态并存 + 邀请即建号）**：管理员生成邀请后可（a）经 `kernel.MailSender` 投递邀请信，或（b）复制链接手动出示（roadmap 产品事实两形态均可用）。受邀者**无需预置账号**：凭邀请链接激活时自设用户名 / 姓名 / 密码完成建号；用户名冲突 fail-closed 重填；密码过当时生效策略。
- **生命周期（I-005）**：邀请默认 7 天有效（可配置）；一次性（激活成功即作废）；管理员可随时撤销（即时失效）；重发 = 撤旧发新（新令牌新效期，重发冷却对齐 60 秒）。过期 / 已用 / 已撤销的邀请接受时返回可核对的受控失败语义。

### §4 会话语义（I-008，non-blocking 提前投影）

- 自助恢复完成、管理员重置沿用现行设密语义（token_version 前移 → 该账号其余会话失效）；自愿改密保持现行行为不变；邀请激活为首次建号，无既有会话问题。本条为现状投影，不引入新机制。

### §5 边界与验收对齐

- 无 SMS / 推送 / IM、模板中心、多邮箱 / 别名、组织权限、OIDC、业务域；不改 Profile 默认集 / 模块矩阵 / Manifest 装配语义；不重开 VP-012～018。
- 邮箱枚举、重放、open-relay、邀请滥用等安全/符合性 gap 归 VP-009 / VP-010 持续程序，不进本波分母。
- R2/R4 验收对照 VP-017 当时默认渠道（预期 mock 出站记录端到端取信）。

## 为什么

- 九个信息项全部有用户书面裁决留痕（Root D-002 三项 + 本轮五项 + I-006 产品事实），P-005 门禁全数解除。
- 恢复/时效面与 VP-018 同构使实施复用最大；MFA 第二因子门封死 V-F076 旁路；策略起步宽松符合渐进方向且不破坏既有体验；邀请即建号与 VP「受邀者在无既有账号情况下完成激活」一致。

## 未选方案

- 策略默认即较严（min 10 + 三类字符）：立即收紧现有创建/重置体验，未被选。
- 邀请须预置账号：与 VP 描述不一致、流程长，未被选。
- 72 小时邀请窗口：更短暴露期但跨周协作易过期，未被选。
- 登录时对不合策略账号强制改密：与 VP「不锁死既有账号」冲突，未被选。
- 恢复不撤销其他会话：偏离现行 token_version 机制且安全性弱一档，未被选。
