# D-001 · F-008 修复方案：流水 id 加入同毫秒单调序（回放排序恢复创建序）

## 决策

`newID` 调整为 `UnixMilli + 进程内同毫秒单调计数（8 hex）+ 随机后缀`：

```go
fmt.Sprintf("%016x%08x%s", now.UnixMilli(), seq /* atomic 递增 mod 2^32 */, randHex(12))
```

排序语义：跨毫秒由毫秒前缀主导；**同一毫秒内由计数顺序主导（= 创建序）**；随机后缀仅防主键冲突（多实例同毫秒同 seq 时尾部区分）。注释同步修正（原"毫秒前缀保证同秒创建序"假设在"同毫秒"处失效）。

## 取舍

| 方案 | 评价 | 结论 |
|------|------|------|
| A：id 内嵌同毫秒单调计数 | 改动最小（一行生成器 + 注释），直接恢复 D-002 §1 的 (created_at, id) 排序契约；单实例（sqlite & pg 本项目部署）下 seq 唯一；多实例非目标（README R5） | **采纳** |
| B：回放改按 SQLite `rowid` 排序 | 跨方言不可行（pg 无稳定写入序） | 拒绝 |
| C：新增 `seq` 列 + 迁移 + 回放双键改序 | 迁移（双方言 checksum/既有库）、DDL 与回放面全改，复杂度高 | 拒绝（除非未来多实例需求出现） |
