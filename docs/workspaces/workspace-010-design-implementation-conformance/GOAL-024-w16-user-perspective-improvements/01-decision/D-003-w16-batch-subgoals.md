# D-003 · W16 实施分批与子目标规划

## 1. 触发

D-001 已列出三批推荐分组；D-002 完成技术方案后，需要将分批落为可独立交付的治理子目标。用户要求“渐进添加子目标承载治理上下文”，因此本决策冻结分批方案，并**先创建批 A 子目标**；批 B、批 C 在批 A 完成后渐进添加。

## 2. 分批决策

| 批 | 子目标 | 范围 | 创建时机 |
|----|--------|------|----------|
| A | `GOAL-025-w16-rectification-batch-a` | W16-F01 首次改密 / W16-F07 一键下线其他 / W16-F08 验证码刷新 + MFA 备份 | 本决策立即创建 |
| B | `GOAL-026-w16-rectification-batch-b` | W16-F02 文件预览复制 / W16-F03 导入模板与错误定位 / W16-F04 金额格式化与调账警示 | 批 A 完成后渐进添加 |
| C | `GOAL-027-w16-rectification-batch-c` | W16-F05 Cron 预览 / W16-F06 监控自动刷新 / W16-F09 字典 Badge / W16-F10 页脚版权 | 批 B 完成后渐进添加 |

> 编号为预计编号；实际以创建时 `goal-tree.md` 当前最大编号 + 1 为准。若批 A 过程中出现独立澄清/验证目标，编号顺延，不机械占用上述编号。

## 3. 父目标承接关系

- 批 A/B/C 均作为 `GOAL-024-w16-user-perspective-improvements` 的下级子目标。
- GOAL-024 保持 `active`，直到全部整改子目标完成并终审后方可 `done`（与 W14/W15 模式一致）。
- 每个子目标使用五件套独立承载方案冻结、实施、回归、审计与关门记录，避免把 10 项实现细节堆入父目标。

## 4. 本决策立即执行项

1. 在 `00-meta.md` 成功标准中增加 R1～R3 与 S5 关门检查点，progress 重算为规划完成后的派生值。
2. 创建 `GOAL-025-w16-rectification-batch-a` 五件套并登记到 `goal-tree.md`。
3. 批 B/C 暂不创建文件夹；仅在 D-003 保留规划，待批 A 关门后按渐进方式添加。

## 5. 未选方案

- **不一次性创建全部三个子目标**：用户强调“渐进添加”，且批 A 完成前批 B/C 的上下文尚未成熟；一次性创建会增加维护噪音。
- **不把 10 项直接放入 GOAL-024 实施**：范围过大，无法独立审计与追溯；与 W14/W15 子目标分批模式不一致。
