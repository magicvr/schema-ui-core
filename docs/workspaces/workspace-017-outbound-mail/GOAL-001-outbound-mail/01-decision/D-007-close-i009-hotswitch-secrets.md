# D-007 · 关闭 I-009：热切换密钥与切换语义（R7 门禁解除）

## 背景

Root I-009（热切换：密钥存储、切失败保留旧 sender、单进程 vs 多实例）是 R7 实施前的最后一个 required 信息门禁。2026-08-24 用户书面裁决（会话问答留痕）：管理面**可填渠道密钥**，采用「**写后不可读回 + 主密钥加密落库**」方案。

## 决定

1. **密钥处理（用户裁决）**：设置页可填写渠道密钥（如 resend api-key）；提交后 API **永不回显**；落库前以本地主密钥加密（主密钥经 env 注入，或首次使用时自动生成并保存于 data/ 目录）；满足现行退出分母「secret 不入库明文可读」。
2. **渠道选择状态**：当前渠道存 DB（初始值取文件层 `mail.channel` 推导结果作为种子）；设置页切换写入 DB 并对后续 `Send` 即时生效（VP-017 配置面「热切换」条款的直接落实，非新增裁决）。
3. **切失败保留旧 sender**：切换时对新配置做可用性校验，失败则保留当前 sender 并向管理面报错——按 VP-017 意图条款执行。
4. **进程语义**：热切换为单进程即时生效；多实例一致性同步仍属非目标（VP-017 非目标清单已冻结该边界），文档如实声明，不假装多副本已同步。

## 为什么

- 方案 2（管理面不收密钥）会让「换生产渠道必须上服务器」，削弱试发/联调闭环；方案 3（明文库）违反退出分母字面，用户未豁免。
- 主密钥加密是满足「不入库明文可读」的最小实现；自动生成分支保证本地双进程默认路径零配置可用。
- 条款 2～4 均可直接从 VP-017 已冻结文本推导，无需再裁决。

## 未选方案

- 管理面不收密钥（运维体验差，被否）。
- 明文入库不回显（需豁免分母条款，未被授权）。
- 多实例广播同步（越界进 A3 非目标）。

## 影响

- I-009 → **verified**；Root 信息项全部闭合，R7 门禁解除。
- GOAL-007 A-001 F-001 residual 同日由用户裁决闭合：outbox 读面**维持 `settings.read`**门禁（accepted-residual；范围 = mock 出站记录读面；复审触发 = R7 权限需要更细粒度时）。
- R7 子目标开设即可开工；加密实现细节（算法/键位）归 R7 目标决策层。
