# D-001 · R3 执行边界与分类规则（提议，待用户确认）

## 上下文

Root R2 于 2026-09-09 关门（GOAL-003 `done 3/3`；A-001 self `pass`、A-002 independent `pass`、A-003 响应 F-001 `fixed`）。R1 已冻结分母与「现在修 vs 另立」规则（GOAL-002 D-001）；I-035-002 四类参照集已由用户书面冻死。R3 现在开工，须先把分类分级规则与逐项必需证据字段写死，再产出对照与分类。

本决策**提议**以下边界；标「待用户确认」的条款在冻结前不得用于放行 C2/C4 门禁。

## 冻结项（可直接执行，不构成方案选型）

| # | 项 | 内容 |
|---|----|------|
| 1 | 对照分母 | 严格取 R1 [包含表 §1.1](../../GOAL-002-r1-denominator-freeze/attachments/r1-denominator-freeze.md) 的 17 面 + Web 抽检；R2 矩阵行号与结论为事实基线 |
| 2 | 参照集 | 四类（模块化单体+组合根 / 基础设施端口 / Schema 驱动 Admin / 同进程基座），不得扩充类别 |
| 3 | 每行四格 | 业界常见做法 → 本仓现状 → 分类 → 不推翻项；缺任一格即该行不成立 |
| 4 | 业界侧取证 | 只用公开、稳定、可外部核对的惯例（框架官方文档 / 长期稳定工程惯例）；不要求付费调研，不使用无法核对的博客主张 |
| 5 | 分类词表 | 仅 `现在修` / `仍 gated` / `接受残余` / `明确不做` 四值；不得自造第五类 |
| 6 | 逐条必需字段 | 证据路径（file:line 或文档锚点）、分类、影响的路线图行（RT-* 或 A 序列）、复审触发或残余范围 |
| 7 | 禁改清单 | 不改生产代码、端口公开语义、Profile 默认集；不消耗 trigger-gated 行；不重开 closed VP；不写 roadmap.md 正文（R4 交 `/vision`） |

## 待用户确认项（P-004 门禁）

| # | 待确认 | 本决策建议 | 为什么不静默 |
|---|--------|-----------|--------------|
| A | **「现在修」条目的归属** | 沿用 R1 D-001 默认 = **另立**：R3 只登记分类与证据，不在本 VP 改代码；唯一例外是 G-001/G-002 文档卫生（R4 执行） | R1 曾冻结「默认另立」，但 VP-035 首波表又允许「范围小、可闭环的现在修」留在本 VP；两处口径需用户在分类结果上确认 |
| B | **「接受残余」的判定权** | 由用户逐条确认（或按 RES-* 原 VP 已有 `accepted-residual` 直接继承） | P-003：残余接受须用户书面；编排器不得自行接受 |
| C | **R3 independent 审计 provider** | 按本会话目标指令用**本地 codex `gpt-5.6-sol` · 思考强度 high**；项目级 `independent-audit-execution.md` 默认 grok build 4.6 | 两处口径冲突（会话指令 vs 项目级默认），且 provider 影响门禁成本；不静默择一 |

## 分级规则（提议）

| 分类 | 判定标准 | 放行后果 |
|------|----------|----------|
| 现在修 | 有证据表明现状偏离已冻结设计或已交付合同，且修复范围小、可在本 VP 证据闭环内完成（仅文档卫生默认落入此类的 R4 子集） | 登记后进 R4 文档卫生或另立；本 VP 不实现端口变更 |
| 仍 gated | 现状为显式接缝/缺席，触发条件未满足（RT-Q03/Q05、A3、KMS 波等） | 保持 RT-* 行状态，不消耗 trigger |
| 接受残余 | 有界、已取证、复审触发明确的剩余风险 | 需用户书面接受（待确认项 B） |
| 明确不做 | 与 Charter 非目标或本 VP 边界冲突的业界做法 | 写入「不推翻项」，不产生工作项 |

R2 缺口候选的**初判**（R3 需逐条取证后定稿，不作冻结）：

- G-001（overview 现时节过期）、G-002（roadmap 锚点/RT-P04/RT-D02 描述滞后）→ 文档卫生，R4 editorial，判据 4。
- G-003（cache seam §2.6 尚描述旧 RateLimiter API）→ 建议「现在修（文档）」；不得替 owner 冻结 Redis 实现，不接受语义缺口为残余。
- G-004（`assembly.NewAuthenticator` 返回 internal 指针且仅 current）→ 需在「现在修（另立兼容性波次）/ 接受残余 / 明确不做（B+ 边界内）」之间由用户裁决。

## 未选方案

- **把 R3 做成全仓业界调研**：违背有界原则与 I-035-002 冻死的四类。
- **先按「主流实践」改代码再回头补分类**：VP-035 已禁止（禁止先改路线图/实现再找证据）。
- **由编排器直接接受残余或驳回 finding**：P-003/P-004 禁止。
