# D-003 · R6 追加 C7 控制位与搜索配对纠偏

## 决定

用户在 C5 交付后提出三项 UI 反馈，仍属 R6 同一列表视觉分母。按 D-012 先例回开同一 `GOAL-007-list-page-visual-alignment`，追加 C7（不新建 GOAL-008），并把 R6 检查点由 6 项扩为 7 项。

C7 合同：

1. **视觉强调**：“列配置”与“保存为视图”两个触发器参照 `raw/new-table` 范例页各配一个图标（列图标 / 加号），图标 `aria-hidden`，不替代可访问名称。
2. **搜索配对回调（纠正 C5 回归）**：搜索按钮回到其关键词输入所属的网格单元内，与输入贴合为同一控件（`-ml-px` 重叠 + 内侧圆角拉平）；筛选网格末位操作单元只保留重置与展开/收起。C5 曾把提交按钮移入该操作单元，破坏了 A-003 / W13 T-03 已冻结的配对机制。
3. **视图表单位置**：“添加视图”表单及“更新视图”“删除视图”从页面级 actions 行移入视图标签组所在的 surface，紧随标签组下方，贴近触发它们的“保存为视图”按钮。

## 理由

三项都是同一范例对齐合同的局部纠偏。第 2 项不是新设计取舍，而是**回退一次回归**：本项目的搜索控件与范例页的单一“查询”按钮机制不同——范例页的查询按钮提交整张筛选表单，本项目的搜索按钮提交其所属关键词输入，因此必须与输入同格贴合，不能并入筛选操作单元。C5 的改动把两种机制混为一谈。

第 3 项纠正的是空间直觉：页面级 actions 行位于筛选栏之下、列表之上，把视图表单放在那里会使它与触发按钮相距数百像素。视图表单归属于视图标签组，应在其 surface 内呈现。

## 未选方案

- 不新建 GOAL-008 或新 VP：同一视觉合同拆成多个重叠目标会增加台账与 Root 阶段重复成本。
- 不保留 C5 的“搜索按钮进操作单元”布局：那与冻结的 A-003 配对规则和本项目控件机制冲突。
- 不为视图表单引入弹层/模态：会新增交互面与可访问性范围，超出“位置纠偏”的边界。

## 门禁

C7 需实现、定向回归与自审证据完成后，才可进入 C6 修订审计；C5 的 E-004 不再代表当前交付状态。R5-I-004 仍开放，R6/C7 不得关闭 R5、Root 或 VP-037。审计模式按常规、可逆的 UI 纠偏继续记为 `self`。
