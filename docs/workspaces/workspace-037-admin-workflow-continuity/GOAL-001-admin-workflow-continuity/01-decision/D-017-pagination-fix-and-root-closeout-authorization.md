# D-017 · 分页缺陷整改与 Root 关门授权

## 决定

2026-09-18，用户报告两个使用中发现的缺陷，并作出书面授权：

> 发现个新问题，列名翻页控件中有一个选择每页显示多少条的下来选框，其中"10"是不生效的，而且默认显示是"10"，但是实际上生效的是"20"。需要修正一下这个下拉空间的逻辑（并且把默认改成20，但要确保10页生效）。另外就是页面跳转的确认按键应该显示为"跳转"，而非"搜索"（对应的英文同理）。修改这两个问题后，授权走根目标关闭流程。

据此：

1. 开设整改子目标 **`GOAL-011-pagination-page-size-contract`**（Root 下的非纲领子目标，不改变 Root 六阶段分母与 `progress`），承接两个缺陷的复现、修正与防复发。
2. **授权性质**：该指令同时构成 `GOAL-006-r5-composition-acceptance` 的 **`R5-I-004`（required；用户是否书面确认 Root/VP 关门？）** 的书面确认来源，并附带一个前置条件——「修改这两个问题后」。因此关门流程必须在 `GOAL-011` 修正完成并验证通过之后执行；`GOAL-011` 的 `E-003`/`A-001` 即该前置条件的解除证据。
3. **关门流程范围**（按用户授权执行）：闭合 `GOAL-008 A-002 F-001` 之外的最后一环——把 `R5-I-004` 落盘为 `verified`、闭合 `A-001 R5-GATE-001` / `A-002 F-001`（`fixed`）、勾选 `GOAL-006` C4 并投影 `done · 4/4`、投影 Root `GOAL-001` 为 `done · 6/6`、填写并关闭 VP-037（含关门 Vision Review）、同步 `goal-tree.md` / `workspace.md` / `docs/vision/roadmap.md` / `docs/vision/workspaces.md` / Charter 组合快照。

## 未选方案

- **先关门再修缺陷**：用户明确把修正作为授权的前置条件；且带着已知用户可见缺陷关门会削弱 VP-037 判据 #7（分页展示）的证据；不采纳。
- **把缺陷整改并入 R2/R6 回开**：回开会把已完成的纲领检查点重新变为未完成，与用户「授权走关门流程」的意图冲突；按 `GOAL-008/009/010` 先例以平行整改子目标承接；不采纳回开。
- **只把前端默认值改成 20 而不加守卫**：正是本次缺陷的成因（跨层常量漂移 + 测试固化错误契约）；不采纳（`GOAL-011 D-001`）。
- **顺带统一其它表面的分页默认值**：超出用户报告范围，且那些表面显式带参、行为正确；不采纳。

## 边界与不变量

- 不改 `apps/api`（服务端 20 与 `DefaultPageSize` 语义不变）。
- 关门流程不改变 VP-037 的方向级退出判据文本，只补关门证据与投影。
- gated 非目标（实体全文检索、批量结果中心、组织/数据权限、新业务域、Redis/MQ/多实例）不因关门解禁；`I-037-005`、`R5-I-005`、`V-F124`、`GOAL-008 A-002 F-002`、`GOAL-009 A-001 F-001/F-002` 仍按各自台账保持 deferred/recommended。
