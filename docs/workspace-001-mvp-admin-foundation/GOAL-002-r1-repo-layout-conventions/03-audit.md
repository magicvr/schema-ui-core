### Findings

#### F-001 · required · med · `apps/*` 首次创建权归属不清

- **现象**：D-001 写「**可**创建空的 `apps/web`、`apps/api` 占位」；GOAL-003/004 又以各自目录为交付根。goal-tree 写「002 宜先落约定」，但无硬依赖与互斥规则。
- **风险**：并行实施时可能出现双重 init（空 README vs `go mod`/`npm create`）、目录冲突或约定文档与真实树短暂分叉。
- **证据**：本目标 `01-decision.md` D-001.2；GOAL-003/004 `00-meta` 路径声明；`goal-tree.md` 说明段。
- **建议闭合路径**：在 002 决策中二选一并写死——**(A)** 002 **只写约定文档**，禁止创建 `apps/*`，由 003/004 首次建树；或 **(B)** 002 **仅** `.gitkeep`/一行 README 占位，003/004 在既有空目录上填充且不得改路径语义。编排器推进前闭合。

#### F-002 · required · med · 成功标准「本地运行入口」与 R1 阶段交付物错位

- **现象**：成功标准要求「本地运行入口（命令级）在根 README 或约定文档可找到」，但本目标明确不交付可运行服务/前端；003/004 才产生真实命令。
- **风险**：为关门而编造命令 → 与后续 scaffold 漂移；或 002 无法独立验收而假性阻塞。
- **证据**：`00-meta.md` 成功标准第 4 条 vs D-001「不在本目标实现 HTTP/UI」。
- **建议**：将标准改为两档——**(1)** 必达：布局/包管理/边界文档；**(2)** 运行命令：写「期望命令契约」并标注 **owned-by GOAL-003/004**，或 002 关门只要求链到姊妹目标 README 占位，不以「可执行」为 002 独有门禁。

#### F-003 · recommended · low · 「宜先完成」未升格为可追踪依赖

- **现象**：树与 meta 备注均为软序（宜先）；无信息项/检查点表达「003/004 实施前 002 文档已合并」。
- **风险**：低——D-004 已预锁路径；仍有文档滞后导致路径漂移的小概率。
- **建议**：在 Root 或 002 增加显式检查点「布局约定 merged」作为 003/004 开工推荐门禁（可为 non-blocking 流程约定，不必升 required 除非团队反复踩坑）。

#### F-004 · recommended · low · 无本目标独立 I-00N 表项（可接受）

- **现象**：信息表写「无新增 required」，端口/env 细节推给 002/003。
- **评价**：与 Root I-STACK verified 一致，**可接受**；但若 002 将写入默认端口，建议补一条 non-blocking I-002-00N 或直接在决策写死建议值（D-004 已建议 API `:8080`）。

### 必改项汇总

1. **F-001**：明确 `apps/*` 首次创建归属（A 或 B）。
2. **F-002**：修正「本地运行入口」成功标准，避免约定目标独吞可运行验收。
